# Evidence Sources and Collection Outcomes

This document describes implemented source families, what a successful observation supports, and important limits. Every collector result is included in the JSON report's `collectionOutcomes` and diagnostic checks where applicable. A zero-item success means no matching record was returned by that collector; it does not establish that the system has never contained relevant evidence.

| Source | Implemented method | What a positive observation supports | Limitations |
| --- | --- | --- | --- |
| Minecraft installations | Supported launcher/default path discovery and optional user-provided directory | Directory existed and was selected for scanning | Discovery is not exhaustive; launcher-specific/custom locations may be missed |
| Minecraft mods | Reads immediate `mods` JAR entries, ZIP metadata and SHA-256; static bytecode/signature heuristics | File present in discovered mods directory; metadata/hash and static patterns observed | Does not prove loaded in a match; private/obfuscated mods may be unknown; bytecode patterns can be benign |
| Processes | Windows process enumeration with metadata, WMI command line where available, parent PID/name, start time, executable hash, Java version/architecture | Process instance was observed at collection time; Minecraft attribution requires recognized game/client launch marker | Process metadata and command line can be denied/redacted; process may exit/reuse PID; selection is targeted, not a full inventory |
| Loaded modules | `Process.Modules` enumeration for selected target processes; file hash, size, timestamp, base address and WinVerifyTrust metadata when available | Module path was enumerated in a specific process instance | Protected/other-bitness process restrictions; a module is not necessarily malicious; not a complete mapping of manually mapped code |
| Private executable memory indicator | Bounded `VirtualQueryEx` / `ReadProcessMemory` probe for `MZ` at executable private regions | A sampled region began with PE DOS signature | Heuristic only; may miss injection; access denied/unsupported; does not inspect arbitrary bytes or establish behavior |
| Java agents / launch args | Redacted command line parsing for startup agent references and supported launch markers | Argument/configuration reference was present | Does not prove agent existence, successful load, or use; dynamic attach not observed |
| File discovery | Bounded scan of selected Downloads/Desktop/Temp locations for `.jar`, `.exe`, `.dll`; hidden/system attributes | Matching file/attribute existed at scan time | Bounded depth and extension; access denied and concurrent changes; no proof of execution |
| Recycle Bin | Parses supported Windows `$I` versions and inspects paired `$R` data when available | Metadata recorded a deleted path/time; preserved payload can be hashed/inspected | Purged, Shift+Deleted, unsupported, or inaccessible records are absent; metadata-only is not content proof |
| Prefetch / historical artifacts | Parses supported Prefetch and Windows history artifacts available to the collector | OS artifact contains an execution-related record | Not exhaustive, OS/configuration-dependent, compression/parser/ACL limitations; no command-line or match association guaranteed |
| Registry / UserAssist | Reads implemented selected current-user/system keys | Selected key/value existed at collection time | Not all artifacts are parsed; missing values do not prove no execution |
| Services and drivers | Selected service registry entries and System event records; signature checking where present | Service configuration or installation event observed | Does not prove driver loaded or interacted with Minecraft; event log and registry permissions limit coverage |
| USB storage | Enumerates implemented USBSTOR records | Storage device history is present | Does not provide a complete connection timeline or prove files were executed from it; HID devices are not covered |
| Browser history (optional) | Read-only SQLite query of known domain matches in supported Chromium histories; WebKit visit timestamp conversion | Matching URL row exists in selected profile history | Separate explicit opt-in; copied DB/WAL may be inconsistent; site visit alone is weak, non-execution evidence |
| Online mod verification (GUI opt-in) | Configured hash-only provider lookups | Provider returned a match/response for a hash | Network unavailable or provider gaps produce unknown; no files/raw memory uploaded; CLI leaves this disabled |

## Outcome and confidence semantics

Collector outcomes distinguish success, partial success, unavailable, permission denied, unsupported, timeout, cancellation, and error. Missing/denied/corrupt records are not interpreted as tampering. Findings should retain artifact location/source, process identity when relevant, timestamp source, hash if collected, reason, supporting/contradicting evidence, and limitations. File presence, installation, configuration reference, historical execution, process module load, Minecraft association, and session activity are separate evidence claims.

A report's SHA-256 seal covers the exported payload (after privacy sanitization). It detects modification but does not provide author authentication or chain of custody.
