## 1. Research Governance & Claim Verification Methodology

Forensic software must not be built upon community folklore or unverified assumptions. To establish an unassailable engineering foundation, every technical proposition regarding Windows operating system internals, JVM execution, and forensic artifact persistence has been subjected to rigorous verification against official Microsoft documentation, the Java Virtual Machine Specification, and peer-reviewed digital forensics research.

---

## 2. Master Claim Register

The register catalogs key technical claims, their empirical validation status, and their direct impact on the platform's architectural design:

| Claim ID | Original Forensic Claim | Validation Status | Authoritative Evidence & Documentation | Operating Conditions & Constraints | Technical Correction & Clarification | Direct Architecture Impact |
| :---: | :--- | :---: | :--- | :--- | :--- | :--- |
| **CLM-01** | *"Windows Prefetch records a complete and exhaustive history of every program executed on the computer."* | **INCORRECT** | Microsoft Windows Internals (7th Ed., Part 2); SCCA format specifications. | Windows Client only (disabled on Windows Server; often disabled on SSDs). Holds max 1,024 entries. | Prefetch stores only the **last 8 execution timestamps** and a lifetime run count. It does **not** record execution duration, exit time, or command line arguments. | Architecture explicitly treats Prefetch as a bounded historical indicator, never claiming it proves match concurrency. |
| **CLM-02** | *"An executable's presence in Amcache (`Amcache.hve`) proves that the user executed the program."* | **INCORRECT** | RFC 3161; *Investigating Amcache.hve* (Yogesh Khatri, SANS DFIR). | Windows 8, 10, 11. Locked by kernel during runtime. | Amcache records application inventory for compatibility. Files can be indexed during Windows search, file copying, or updates **without user execution**. | Amcache is classified as `EvidenceCategory.Disk` or `Historical`, **never** as sole proof of execution. |
| **CLM-03** | *"BAM/DAM registry timestamps represent exact program exit times or execution durations."* | **PARTIALLY VERIFIED** | Windows 10/11 Kernel Power Management Architecture (`ntoskrnl.exe!BamLogProcess...`). | Windows 10 build 1709+ and Windows 11. Stored in `SYSTEM` hive. | BAM records the timestamp of the **last state transition** (focus change or termination), not total duration. Semantics drift across Windows 10 vs 11 builds. | BAM timestamps are modeled with `TemporalUncertainty` of $\pm 5\text{ minutes}$ and must be corroborated by Prefetch. |
| **CLM-04** | *"Reflective DLL injection can be detected by querying `EnumProcessModulesEx` on the target process."* | **INCORRECT** | Stephen Fewer (Harmony Security, Reflective DLL Injection original paper); Win32 PEB specs. | 32-bit and 64-bit Windows user-mode. | Reflective DLL injection manually copies PE sections and resolves imports in memory, **bypassing the PEB module list** (`InLoadOrderModuleList`). | Architecture acknowledges `EnumProcessModulesEx` is insufficient for reflective DLLs; specifies user-space `VirtualQueryEx` page scanning in future roadmap. |
| **CLM-05** | *"A local proxy listening on `127.0.0.1` proves that Minecraft network traffic was intercepted or manipulated."* | **INCORRECT** | RFC 1122; Win32 Extended TCP Table specifications (`iphlpapi.dll!GetExtendedTcpTable`). | Universal on TCP/IP stacks. | Software developers, VPNs, and local services routinely bind to localhost. Presence of a listening socket does not prove Minecraft traffic was routed through it. | Architecture requires verifying that the active TCP socket for `javaw.exe` connects directly to `127.0.0.1` before raising a proxy finding. |
| **CLM-06** | *"A USBSTOR registry record proves that a player used a macro keyboard or hardware cheat."* | **PARTIALLY VERIFIED** | Microsoft USB Device Class Registry Specifications; Windows Driver Architecture. | Universal on Windows. | USBSTOR records only Mass Storage class devices (flash drives). Input automation devices (Arduino, Teensy) register under the **HID** class, not USBSTOR. | Architecture splits USB auditing into `USBSTOR` (removable drives) and `HIDClass` (input microcontrollers) with distinct schemas. |
| **CLM-07** | *"Static bytecode patterns (e.g. constant pool strings) establish that a cheat capability was actively used in game."* | **INCORRECT** | Java Virtual Machine Specification (Java SE 8/17/21, Section 4.4); ASM Bytecode Library. | Any Java ClassLoader. | Bytecode defines static potential capability; it does not prove execution, feature toggle status, or in-game usage. | Architecture maps bytecode strictly to `CapabilityModel` (`CAPABILITY_CONFIRMED`), never to an active cheat verdict without server correlation. |
| **CLM-08** | *"An unsigned DLL mapped into a 64-bit Java process is conclusive proof of unauthorized code injection."* | **INCORRECT** | Java Native Access (JNA) Architecture; LWJGL Native Loader Specifications. | Standard Java running on Windows. | Legitimate Java libraries (JNA, OpenAL, Discord SDK) unpack **unsigned native DLLs into `%TEMP%`** and load them via `System.load()`. | Architecture inspects internal PE export tables to verify known JNA symbols (`Java_com_sun_jna_...`), classifying them as `Informational`. |
| **CLM-09** | *"USN Journal records prove deliberate anti-forensic concealment if files were deleted before a scan."* | **PARTIALLY VERIFIED** | Microsoft NTFS Technical Specification; Windows Internals File Systems. | NTFS formatted volumes with journaling enabled. | The USN Journal records raw filesystem state transitions. Temporary files are created and deleted constantly by launchers and browsers. | Architecture requires matching deleted filenames against known cheat signatures before flagging anti-forensics. |
| **CLM-10** | *"System Resource Usage Monitor (SRUM) provides real-time network packet inspection of cheats."* | **INCORRECT** | Microsoft Windows ESE Database Architecture (`SRUDB.dat`); SANS DFIR SRUM Analysis. | Windows 8, 10, 11. Extracted via ESE API. | SRUM aggregates byte counts per application across **60-minute windows**. It records zero packet headers, zero URLs, and zero destination IPs. | Architecture limits SRUM use to high-level hourly bandwidth correlation, explicitly forbidding packet tampering claims. |
| **CLM-11** | *"NTFS file creation timestamps ($STANDARD_INFORMATION) reliably establish when a file arrived on the host."* | **PARTIALLY VERIFIED** | Windows File Systems Forensics; Carrier & Spafford (NTFS Metadata). | NTFS volumes. | `$STANDARD_INFORMATION` timestamps can be modified in user-mode via `SetFileTime` (timestomping). `$FILE_NAME` in MFT is resistant to user-mode API writes. | Architecture compares `$STANDARD_INFORMATION` against `$FILE_NAME` in MFT to detect timestomping anomalies. |
| **CLM-12** | *"JVM command-line arguments captured from the PEB represent the complete set of active Java agents."* | **PARTIALLY VERIFIED** | Oracle JVM Tool Interface (JVMTI) Specs; HotSpot Virtual Machine Attach API Specs. | Standard OpenJDK / Oracle JDK. | Captures startup agents (`-javaagent:`). Agents loaded dynamically post-startup via `VirtualMachine.attach()` **leave no command-line trace**. | Architecture explicitly documents dynamic attach as an observational gap in Layer C (`16-OPEN-QUESTIONS-AND-RESEARCH.md`). |
